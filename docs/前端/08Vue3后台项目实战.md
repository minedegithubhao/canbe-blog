# Vue3后台项目实战

很多“Vue 项目实战”文章，一上来就直接写页面。  
但真正做后台系统时，最关键的不是某一个页面，而是：

> 工程骨架、接口封装、路由、状态、鉴权，这些基础设施有没有先搭稳。

这一篇最大的价值，在于它不是只讲概念，而是完整记录了一条后台项目从零落地的路线。  
这里不会再把代码抽掉，而是按真实开发顺序把它们串起来。

## 一、先起工程：Vue、Element Plus、Axios、Sass 是最小骨架

### 1. 创建项目

```bash
npm init vue@latest

cd big-event
npm install
```

### 2. 安装基础依赖

```bash
npm install element-plus --save
npm install axios
npm install sass -D
```

在 `main.js` 里接入 Element Plus：

```ts
import { createApp } from 'vue'
import ElementPlus from 'element-plus'
import 'element-plus/dist/index.css'
import App from './App.vue'

const app = createApp(App)
app.use(ElementPlus)
app.mount('#app')
```

### 3. 调整目录

后台项目最好从一开始就分层：

- `api`：接口调用
- `utils`：工具函数和请求实例
- `views`：页面级组件
- `assets`：静态资源

## 二、登录和注册页通常是第一个联调入口

这一页之所以重要，不只是因为用户会先看到它，而是因为它同时验证了：

- 组件库有没有接进来
- 表单能不能正常工作
- 请求层是不是通了
- 跨域代理是否生效

### 2. 自定义确认密码校验

```ts
const rePasswordValid = (rule, value, callback) => {
  if (value == null || value === '') {
    return callback(new Error('请再次确认密码'))
  }
  if (registerData.value.password !== value) {
    return callback(new Error('两次输入密码不一致'))
  }
  callback()
}

const registerDataRules = ref({
  username: [
    { required: true, message: '请输入用户名', trigger: 'blur' },
    { min: 5, max: 16, message: '用户名的长度必须为5~16位', trigger: 'blur' }
  ],
  password: [
    { required: true, message: '请输入密码', trigger: 'blur' },
    { min: 5, max: 16, message: '密码长度必须为5~16位', trigger: 'blur' }
  ],
  rePassword: [
    { validator: rePasswordValid, trigger: 'blur' }
  ]
})
```

### 3. 注册接口

在 `src/api/user.js` 中：

```ts
export const registerService = (registerData) => {
  const params = new URLSearchParams()
  for (let key in registerData) {
    params.append(key, registerData[key])
  }
  return request.post('/user/register', params)
}
```

页面里调用：

```ts
import { registerService } from '@/api/user.js'

const register = async () => {
  let result = await registerService(registerData.value)
  if (result.code == 0) {
    alert('注册成功!')
  } else {
    alert('注册失败!')
  }
}
```

## 四、跨域问题别靠猜，前端开发期直接配代理

### 1. `request.js` 统一前缀

```ts
import axios from 'axios'

const baseURL = '/api'
const instance = axios.create({ baseURL })

instance.interceptors.response.use(
  result => result.data,
  err => {
    alert('服务异常')
    return Promise.reject(err)
  }
)

export default instance
```

### 2. `vite.config.js` 配代理

```ts
import { fileURLToPath, URL } from 'node:url'
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'

export default defineConfig({
  plugins: [vue()],
  resolve: {
    alias: {
      '@': fileURLToPath(new URL('./src', import.meta.url))
    }
  },
  server: {
    proxy: {
      '/api': {
        target: 'http://localhost:8080',
        changeOrigin: true,
        rewrite: (path) => path.replace(/^\/api/, '')
      }
    }
  }
})
```

## 六、路由应该在项目早期接入，因为它决定页面骨架

### 1. 安装并创建路由器

```ts
import { createRouter, createWebHistory } from 'vue-router'
import LoginVue from '@/views/Login.vue'
import LayoutVue from '@/views/Layout.vue'

const routes = [
  { path: '/login', component: LoginVue },
  { path: '/', component: LayoutVue }
]

const router = createRouter({
  history: createWebHistory(),
  routes: routes
})

export default router
```

### 2. 子路由和 `router-view`

后台项目真正开始长页面时，`Layout` 往往会成为壳层，然后子页面通过 `router-view` 注入进去。

## 七、Pinia 不是可选装饰，它是登录态和用户态的核心承载

### 1. 接入 Pinia

```ts
import { createPinia } from 'pinia'

const pinia = createPinia()
app.use(pinia)
```

### 2. 定义 token store

```ts
import { defineStore } from 'pinia'
import { ref } from 'vue'

export const useTokenStore = defineStore('token', () => {
  const token = ref('')

  const setToken = (newToken) => {
    token.value = newToken
  }

  const removeToken = () => {
    token.value = ''
  }

  return {
    token,
    setToken,
    removeToken
  }
}, {
  persist: true
})
```

## 八、请求拦截器要负责自动带 token，响应拦截器要负责统一处理 401

### 1. 请求拦截器

```ts
import axios from 'axios'
import { useTokenStore } from '@/stores/token.js'

const instance = axios.create({ baseURL: '/api' })

instance.interceptors.request.use(config => {
  const tokenStore = useTokenStore()
  if (tokenStore.token) {
    config.headers.Authorization = tokenStore.token
  }
  return config
})
```

### 2. 响应拦截器处理未登录

```ts
import router from '@/router'

instance.interceptors.response.use(
  result => result.data,
  err => {
    if (err.response && err.response.status === 401) {
      router.push('/login')
    }
    return Promise.reject(err)
  }
)
```

## 十、文章分类列表是后台业务页开始真正展开的地方

### 1. 分类查询逻辑抽成 hook

```ts
export default function useCategory() {
  const menuItems = ref({})

  const articleCategory = async () => {
    let result = await articleCategoryService()
    menuItems.value = result.data
  }

  return {
    menuItems,
    articleCategory
  }
}
```

### 2. 分类增删改的固定套路

这里把这一整条链路都拆清楚了：

- 弹窗页面
- 表单模型和校验规则
- 按钮事件
- 新增接口
- 修改接口

这也是后台业务页开发的一种固定套路：

1. 先有列表
2. 再有弹窗表单
3. 然后区分新增与编辑
4. 最后做删除和确认框

## 十一、这一整套实战里最重要的不是页面，而是分层

把这里压缩成一个工程模型，其实就是：

- `views`：页面展示
- `api`：接口请求
- `utils/request.js`：请求实例和拦截器
- `router`：页面跳转和布局骨架
- `stores`：全局状态
