# 从五大角度完成对项目的理解

## 一、业务认知层

**核心定位**：甄别是否只会写代码、不懂业务价值，掌握项目存在的底层意义

**核心自查问题**

- 项目服务对象是谁？核心业务痛点有哪些，未落地项目会产生哪些业务问题？

- 完整业务闭环是什么？上下游依赖哪些系统，存在哪些人工低效卡点？

- 业务核心评判指标是什么？和技术性能指标的区别？

- 核心流程删减后，会影响哪些核心业务场景？

- 项目需求是否存在变更？背后的业务矛盾是什么，如何适配调整？

**判定标准**：仅罗列功能、说不清业务痛点与价值，为表层代码参与，无业务认知。

## 二、数据链路层

**核心定位**：甄别是否深度参与数据全流程设计，而非仅使用现成数据

**核心自查问题**

- 数据分为哪些类别？原生数据存在哪些质量问题，对应治理清洗方案是什么？

- 数据存量、增量规模如何？选择全量/增量更新的核心原因？

- 完整数据流转链路分哪些环节？各环节作用与核心瓶颈是什么？

- 冷热数据如何分层存储？数据延迟、丢失、重复的兜底校验机制？

- 数据如何分层设计？各层级的用途和业务适配场景？

**判定标准**：仅简单描述数据处理，说不清数据治理、同步策略、分层逻辑，为浅层数据使用。

## 三、架构与技术选型层

**核心定位**：甄别技术是照搬demo，还是结合业务自主权衡、落地设计

**核心自查问题**

- 各技术组件的选型理由是什么？对比过哪些替代方案，核心权衡维度？

- 各组件如何协同支撑业务？模块边界如何划分，拆分依据是什么？

- 架构落地过程中，遇到的兼容、并发、部署难题及解决方案？

- 针对业务特性，做了哪些定制化改造？通用方案为何无法适配？

- 线上架构的监控、扩容、容灾机制是什么？如何应对高并发场景？

**判定标准**：只会堆砌技术名词，无选型权衡、落地踩坑、定制优化思路，为单纯框架复用。

## 四、落地效果与瓶颈优化层

**核心定位**：甄别是否具备线上落地、性能调优能力，而非仅完成本地demo开发

**核心自查问题**

- 项目上线后，业务、技术指标有哪些量化提升？对应优化改造点是什么？

- 项目运行的核心性能瓶颈是什么？落地过哪些优化方案？

- 线上出现过哪些故障？根因是什么，后续做了哪些长效优化？

- 项目现存短板有哪些？短期、长期迭代优化方案是什么？

- 如何平衡项目效果、响应速度、资源成本三者关系？

**判定标准**：效果描述模糊无量化、无法定位核心瓶颈、无线上复盘优化，仅完成基础开发。

## 五、全局复盘与深度思考层

**核心定位**：甄别是被动执行开发，还是全局参与、具备独立设计思考能力

**核心自查问题**

- 开发过程中是否推翻过原有方案？核心原因是什么？

- 个人独立负责哪些核心模块？跨团队协作如何统一规范、对齐需求？

- 若从零重构项目，业务、数据、架构层面会做哪些优化调整？

- 对比行业同类方案，本项目的核心差异化优势是什么？

- 项目架构是否可复用？复用价值与改造难点是什么？

**判定标准**：无方案迭代、无重构思路、无差异化认知，属于被动执行开发，无全局思维。
