# 项目自述 面试官深挖提问侧重点+高频考题
整体考察逻辑：**是否全程深度参与、业务理解是否落地、技术不是堆框架、清楚每一环设计取舍、能说清真实落地难点**，不纠结底层API名称，聚焦思路、方案、权衡、优化、踩坑。

## 模块1：项目背景（ToB/ToC区分深挖）
### 面试官提问侧重点
1. ToC类：核心用户群体分层、用户真实诉求怎么挖掘、产品侧原始需求来源、同类竞品现存短板、为什么要自研而不采购第三方工具
2. ToB类：企业原有业务流程痛点、业务方提需求的原始矛盾、项目立项动因、业务侧考核指标、落地后业务部门核心诉求是否完全覆盖
3. 通用深挖：项目规模、上线范围、服务对象量级、项目排期、你在项目中的角色（独立负责/协同开发/主导模块）

### 高频问题
1. 当时为什么要做这个项目？不做会带来哪些业务损失？
2. 需求是业务方直接提出，还是你通过数据分析发现痛点推动立项？
3. 同行业有没有成熟解决方案，为什么没有直接复用？
4. 项目面向的核心人群/企业客户最核心的3个诉求是什么？
5. 项目初期需求有没有反复变更？变更原因是什么，怎么协调处理？
6. 你的职责边界是什么，哪些模块是你独立完整负责？

## 模块2：业务流程（业务流程图相关深挖）
### 面试官提问侧重点
1. 完整业务链路闭环逻辑，上下游依赖系统、模块间数据流转关系
2. 流程中关键分支、异常场景、兜底流程、人工介入节点
3. 流程设计权衡：为什么这么拆分步骤，有没有更简化的方案，舍弃了哪些方案
4. 业务与技术的冲突点：业务特殊规则如何通过技术适配

### 高频问题
1. 梳理完整业务流转链路，上下游依赖哪些系统？
2. 流程里有哪些分支判断、特殊异常场景，怎么处理？
3. 最初流程设计版本和最终上线版本有哪些改动，改动原因？
4. 业务侧有哪些特殊规则，技术上怎么兼容实现？
5. 流程中哪个环节是性能瓶颈/出错高发点，怎么优化？
6. 如果去掉其中某一个流程节点，会对业务产生什么影响？

## 模块3：数据（来源、规模、处理链路 核心深挖模块）
### 面试官提问侧重点
1. 多源数据区分：内部业务库、第三方接口、文档、日志、爬虫等不同数据源特点
2. 数据量级、增长速度、数据质量原生问题（缺失、脏数据、格式不统一、重复数据）
3. 完整数据处理链路：采集→清洗→标准化→存储→检索/推理全流程设计思路
4. 数据分层设计、数据权限、数据更新策略（全量/增量/实时）
5. 数据治理方案：脏数据过滤、重复数据去重、缺失值填充的设计逻辑
6. 数据存储选型理由，不同数据分别存在哪里，冷热数据区分策略

### 高频问题
1. 项目数据分为哪几类来源，各类数据有什么天然缺陷？
2. 日常数据增量、存量规模大概是什么水平，数据增长压力怎么应对？
3. 完整的数据处理流程分哪几步，每一步解决什么问题？
4. 原始脏数据主要存在哪些问题，你的清洗规则怎么设计？
5. 为什么选择增量同步而非全量同步，两种方案的优劣对比？
6. 冷热数据如何分层存储，分层的依据是什么？
7. 数据同步过程中出现延迟、丢失如何做兜底校验？
8. 有没有做数据分层，每层的作用是什么？

## 模块4：技术栈（不追问具体API，侧重选型、落地、适配）
### 面试官提问侧重点
1. 每一项技术选型理由，对比过哪些替代方案，取舍依据（性能、成本、业务适配、运维难度）
2. 各技术组件之间协同逻辑，模块间通信、数据流转方式
3. 技术落地难点：框架适配、版本兼容、集群部署、资源占用问题
4. 针对业务场景做的二次封装、自定义逻辑、组件改造思路
5. 线上运维配套方案：监控、日志、扩容、容灾

### 高频问题
1. 整套技术栈每个组件为什么选用，对比过哪些替代方案？
2. 各个技术组件之间如何配合完成整体业务？
3. 使用这套技术栈落地时遇到了哪些兼容性、部署难题，怎么解决？
4. 针对项目业务，你对框架做了哪些自定义封装/改造？
5. 线上如何监控各组件运行状态，指标异常怎么告警处理？
6. 并发量上涨时，整套架构如何扩容？容灾方案是什么？
7. 有没有技术成本约束，如何在有限资源下优化架构？

## 模块5：实现效果（解决问题、指标提升，量化导向）
### 面试官提问侧重点
1. 区分**业务指标**和**技术指标**，必须能量化，不能只说“变快、更好用”
2. 上线前后对比：原有痛点是否完全解决，遗留了哪些未完全解决的问题
3. 指标优化背后对应的技术优化动作，一一对应
4. 用户/业务方真实反馈，落地后的实际业务收益
5. 线上现存短板，后续迭代优化规划

### 高频问题
1. 上线前项目存在哪些核心痛点，上线后分别如何解决？
2. 从业务、性能两个维度，列举核心优化指标及提升幅度？
3. 指标提升是哪部分技术优化带来的，原理是什么？
4. 落地后业务部门/用户真实反馈有哪些正向、负向评价？
5. 当前项目还有哪些未解决的短板，后续迭代计划是什么？
6. 项目上线后有没有出现过线上故障，如何复盘优化？

## 模块6：项目优势（选优模块，深挖差异化、核心竞争力）
### 面试官提问侧重点
1. 和通用开源方案、行业同类项目相比，独有的差异化设计
2. 针对业务场景定制化优化点，通用方案无法适配的地方
3. 架构层面、数据层面、推理/检索层面的创新设计
4. 成本、效率、精度三者之间的平衡优势

### 高频问题
1. 你的项目对比行业同类方案，核心优势体现在哪里？
2. 通用开源框架无法直接适配你们业务，你做了哪些定制化优化？
3. 在成本、性能、效果三者之间，你做了哪些取舍，形成了什么优势？
4. 这套方案能不能复用到其他同类型业务，复用成本如何？
5. 项目最亮眼的设计点是什么，当时是怎么想到这个方案的？

# 二、通用综合深挖高频题（验证真实深度参与）
1. 项目开发周期中，你遇到最大的技术难点是什么，完整梳理解决思路？
2. 开发过程中推翻过哪些方案，推翻的原因是什么？
3. 项目测试阶段发现过哪些隐蔽问题，怎么修复？
4. 如果让你重新做一遍这个项目，你会在架构、数据、技术上做哪些调整？
5. 项目中哪些模块是性能瓶颈，你做了哪些优化手段？
6. 多人协作开发时，怎么保证代码、数据流程规范统一？
7. 上线灰度、全量发布流程是怎样的，如何规避线上风险？
8. 项目产出的核心价值，从技术、业务两个角度分别说明。

# 三、回答核心技巧
1. 不说具体接口/API名称，改用**设计思路、处理策略、实现逻辑**描述；
2. 每道回答绑定「业务场景」，证明不是单纯搭框架，是贴合业务落地；
3. 多提**权衡、取舍、踩坑、复盘、迭代优化**，体现完整参与全流程；
4. 所有效果搭配量化指标，证明你关注线上真实落地结果，不只是demo。
