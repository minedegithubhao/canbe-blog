# 开发环境安装与版本管理：SDKMAN、NVM、pnpm 一次讲清

很多人第一次配开发环境，最容易踩的坑不是“不会安装”，而是下面这种更折磨人的情况：

- JDK 明明装好了，换个项目又要重配
- Git Bash 里 `java -version` 正常，CMD 或 IDEA 里却找不到
- Node 版本一多，前端项目今天能跑，明天就报错
- 包管理器换来换去，磁盘越来越满，依赖越来越乱

说白了，很多环境问题根本不是“没装上”，而是“装得太随意”。

这篇文章就干一件事：把 Java、Node 和包管理器这套开发环境，按最实用、最不容易翻车的方式整理清楚。

- 小白能知道该先装什么、怎么装、为什么这样装
- 有经验的人也能把这篇当速查手册，直接抄命令走

一句话概括本文目标：

> 不是教他把环境“装上”，而是教他把环境“管住”。

---

## 为什么开发环境总是越配越乱

先别急着敲命令，先把这个核心认知建立起来。

### 开发环境最难的地方，不是安装，而是“多版本共存”

因为真实项目几乎都不是单版本世界。

比如：

- 老 Java 项目可能还在 JDK 8
- 新项目已经切到 JDK 17、21
- 一个前端项目要 Node 18，另一个却只能跑在 Node 20

这时候如果还靠“手工覆盖安装”，问题就来了。

可以把它理解成衣柜：

- 手工安装 = 把旧衣服扔一边，新衣服直接塞进去
- 版本管理工具 = 给每一套衣服单独分格子，想穿哪套直接切

所以这篇文章里提到的 3 个工具，本质上都是在做“分格子”这件事：

- `SDKMAN`：管 Java / Maven 这类 SDK
- `NVM`：管 Node 版本
- `pnpm`：管前端依赖安装和包管理体验

它们不是一个层面的东西，但组合起来特别顺手。

## 这套环境到底该怎么装

## 一、Java 这边：用 SDKMAN 管 JDK 和 Maven

### 1. 它是干什么的

如果用一句人话解释：

> SDKMAN 就像 Java 工具箱管理员，帮他统一安装、切换、卸载 JDK、Maven 这些版本。

这就意味着，以后不用再手工下载一堆 JDK 压缩包，解压到各个目录，然后自己改来改去。

### 2. Windows 下安装前准备

这里是基于 Git Bash 的做法。  
安装前先检查 `zip` 是否可用：

```bash
zip -v
```

如果缺失，需要补齐下面两个文件：

- `zip.exe`
- `bzip2.dll`

放到 Git 的 `mingw64/bin` 目录里。

这一步的意思很简单：SDKMAN 安装过程会依赖这些基础命令，缺了它，后面安装就容易卡住。

### 3. 安装 SDKMAN

```bash
curl -s "https://get.sdkman.io" | bash
```

安装完成后，先初始化：

```bash
source "$HOME/.sdkman/bin/sdkman-init.sh"
```

如果希望每次打开终端自动生效，可以加到启动文件里：

```bash
echo 'source "$HOME/.sdkman/bin/sdkman-init.sh"' >> ~/.zshrc
source ~/.zshrc
```

### 4. 验证安装是否成功

```bash
sdk version
sdk list java | grep installed
```

### 5. 命令速查

这部分最适合直接收藏，基本都是高频动作：

```bash
sdk list
sdk list java
sdk install java 25-tem
sdk use java 21.0.2-open
sdk default java 17.0.16-ms
java -version
sdk current
sdk current java
sdk home java 17.0.16-ms
sdk uninstall java 21.0.2-open
sdk list maven
sdk install maven 3.9.6
sdk default maven 3.9.6
sdk uninstall maven 3.9.6
sdk home maven 3.9.6
```

几个最关键的区别可以直接这样记：

- `sdk install`：安装
- `sdk use`：当前终端临时切换
- `sdk default`：设为默认版本，下次打开终端也生效
- `sdk uninstall`：卸载某个版本

如果只记一个点，就记这个：

> `use` 是临时切，`default` 是长期定。

## 二、为什么 Git Bash 里有 Java，CMD 或 IDEA 里却没有

这个坑非常经典，而且极其常见。

现象通常是这样，在 Git Bash 里执行：

```bash
java -version
```

能正常输出，但在 CMD 或 IDEA 里却提示找不到 `java`。

### 根因其实不复杂

不是 SDKMAN 坏了，而是 Windows 系统环境变量没有跟上。

需要重点确认两项：

- `JAVA_HOME`
- `Path` 里的 `%JAVA_HOME%\bin`

例如：

```text
JAVA_HOME=C:\Users\Administrator\.sdkman\candidates\java\current
```

然后重新打开终端，再执行：

```bash
java -version
```

这一步很关键，因为很多人会误以为：

- Git Bash 正常 = 整个系统都正常

其实不是。Git Bash 能找到命令，不代表 Windows 系统和 IDEA 也能找到。

## 三、Node 这边：别手工切版本，直接上 NVM

### 1. 它是干什么的

如果说 SDKMAN 是 Java 世界的版本切换器，那 `NVM` 就是 Node 世界的版本切换器。

它解决的是这个问题：

> 一个项目要 Node 18，另一个项目要 Node 20，怎么不打架？

答案就是：别覆盖装，交给 NVM 管。

### 2. 安装 NVM 之前，先卸载旧 Node

这里这一步强调得非常对。如果旧 Node 不清理，后面最容易路径冲突、命令串版本、系统变量打架。

重点清理这些位置：

- 控制面板里的 Node.js
- `C:\Program Files\nodejs`
- `C:\Program Files (x86)\nodejs`
- `C:\Users\82473\AppData\Roaming\npm`
- `C:\Users\82473\AppData\Roaming\npm-cache`

然后执行：

```bash
where node
```

确认旧路径已经干净。

### 3. 安装 nvm-windows

装完以后先验证：

```bash
nvm version
```

### 4. 配置国内镜像

在 `settings.txt` 中加入：

```txt
node_mirror: https://npmmirror.com/mirrors/node/
npm_mirror: https://npmmirror.com/mirrors/npm/
```

这一步的作用很直接：

- 下载更快
- 更稳定
- 少被国外网络折磨

### 5. 命令速查

```bash
nvm install --lts
nvm install 10.16.3
nvm ls
nvm use 10.16.3
nvm upgrade
nvm -version
nvm uninstall 10.16.3
```

如果要看远端可安装版本：

```bash
nvm ls-remote
```

如果要安装并切换多个版本：

```bash
nvm install 20.18.0
nvm install 18.20.0
nvm install --lts
nvm ls
nvm use 18.20.0
node -v
npm -v
nvm alias default 22.19.0
nvm uninstall 18.20.0
```

这里同样可以提炼一句：

> `install` 是下载版本，`use` 是切当前版本，`alias default` 是设默认版本。

## 四、出现 “nvm 不是内部或外部命令” 时，先别慌，先查 Path

这类报错几乎可以说是 NVM 的新手必经坑。

如果执行：

```powershell
nvm version
```

提示找不到命令，优先查这 3 件事。

### 1. 是否真的安装成功

先确认安装目录下有没有 `nvm.exe`。

如果连这个文件都没有，那不是环境变量的问题，而是安装本身就没完成。

### 2. 是否配置了系统变量

重点检查：

- `NVM_HOME`
- `NVM_SYMLINK`
- `Path` 中的 `%NVM_HOME%`
- `Path` 中的 `%NVM_SYMLINK%`

这一组变量的本质是：

- `NVM_HOME` 指向 NVM 自己
- `NVM_SYMLINK` 指向当前生效的 Node

少一个，都可能让系统“看起来装了，但命令找不到”。

### 3. 终端有没有重开

环境变量改完以后，不重开终端，很多时候根本不会生效。

这个坑非常低级，但真的高频。

## 五、pnpm 不只是更快，它是在帮他“省空间、少踩坑”

很多人第一次听说 `pnpm`，只知道它快。但它真正值钱的地方不只是快，而是：

- 更省磁盘
- 依赖管理更严格
- 对多项目开发更友好

可以把它理解成：

- `npm` 像每个项目都自己囤一份货
- `pnpm` 像统一仓库 + 按需分发

### 1. 安装 pnpm

官方脚本方式：

```bash
# Windows 系统（PowerShell 或 CMD）
iwr https://get.pnpm.io/install.ps1 -useb | iex

# macOS/Linux 系统（Bash 或 Zsh）
curl -fsSL https://get.pnpm.io/install.sh | sh -
```

如果机器上已经有 Node，也可以直接：

```bash
npm install -g pnpm
```

验证安装：

```bash
pnpm -v
```

### 2. 配置镜像和目录

```bash
pnpm config set registry https://registry.npmmirror.com
pnpm config get registry

pnpm config set global-dir D:\pnpm\global
pnpm config set store-dir D:\pnpm\store
pnpm config set state-dir D:\pnpm\state
pnpm config set node-linker hoisted
```

这些配置分别在干什么：

- `registry`：换国内镜像
- `global-dir`：全局包放哪里
- `store-dir`：依赖缓存仓库放哪里
- `state-dir`：状态数据放哪里
- `node-linker hoisted`：兼容一些更依赖传统 `node_modules` 结构的项目

### 3. 命令速查

```bash
pnpm init
pnpm create vite my-project --template react-ts
pnpm add axios
pnpm add -D typescript
pnpm remove axios
pnpm update
pnpm run dev
```

这几条基本已经覆盖日常开发 80% 的操作。

## 这 3 个工具到底怎么分工

| 工具 | 它管什么 | 最适合解决的问题 | 典型命令 |
| --- | --- | --- | --- |
| `SDKMAN` | JDK、Maven 等 Java 生态 SDK | 多版本 JDK / Maven 切换 | `sdk install`、`sdk use`、`sdk default` |
| `NVM` | Node 版本 | 不同前端项目 Node 版本冲突 | `nvm install`、`nvm use`、`nvm ls` |
| `pnpm` | 前端依赖管理 | 安装速度、磁盘占用、依赖管理体验 | `pnpm add`、`pnpm remove`、`pnpm run` |

再压缩成一句人话：

- Java 版本管理，找 `SDKMAN`
- Node 版本管理，找 `NVM`
- 前端依赖安装，找 `pnpm`

不要把它们混成一个工具。

## 常见坑点

### 1. 只会安装，不会“切版本”

这是最常见的问题。很多人装完以后还是默认全局硬用一个版本，等于白装。

### 2. Git Bash 正常，不代表整个系统都正常

如果 CMD、PowerShell、IDEA 不能识别命令，那环境还不能算配好。

### 3. 旧 Node 不清理，NVM 很容易打架

尤其是：

- 旧 `nodejs` 路径还在 `Path`
- `where node` 还能查到老版本

这时就算 NVM 装好了，也可能表现得像没装一样。

### 4. 改完环境变量不重开终端

这个坑很小，但非常高频。命令不生效时，先别急着怀疑工具，先把终端关了重开。

### 5. pnpm 配置目录时别乱配

尤其是 `global-dir`、`store-dir`、`state-dir`，最好一开始就放到一个自己好管理的位置，别今天 C 盘、明天 D 盘，最后自己都找不到。

## 最后

最后给一个一句话记忆口诀：

> Java 用 `SDKMAN`，Node 用 `NVM`，依赖用 `pnpm`，变量统一、终端重开。

如果只给一个最实用的建议，那就是：

- 要切 JDK / Maven，用 `SDKMAN`
- 要切 Node 版本，用 `NVM`
- 要管理前端依赖，用 `pnpm`

配完以后，一定同时验证这 3 个地方：

- `Git Bash`
- `CMD / PowerShell`
- `IDEA / 编辑器`

开发环境真正的目标，从来不是“看起来装好了”，而是：

> 多版本可控、切换清晰、换项目不炸。

做到这一步，后面的开发节奏才会稳。
