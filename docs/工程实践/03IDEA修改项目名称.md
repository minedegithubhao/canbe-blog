# IDEA 修改项目名称：项目名、模块名、目录和 Content Root 一起改

很多人第一次给 IntelliJ IDEA 项目改名时，都会觉得这件事应该很简单。  
但实际操作一遍之后，经常会遇到这些情况：

- 项目名改了，模块名没改
- 文件夹改了，IDEA 里路径红了
- 运行时报错
- 甚至又冒出来一个旧名字的空项目

这里的步骤记录得很细，这篇就按“为什么会翻车 + 正确顺序是什么”来重组。

## 一、为什么改项目名会出问题

因为 IDEA 里的“项目名”其实不是一个名字，而至少有四层：

- Project 名称
- Module 名称
- 本地文件夹名称
- Content Root 路径

如果只改其中一层，剩下几层还指向旧路径，IDEA 就会开始混乱。

## 二、一个更稳妥的改名顺序

### 第 1 步：先改 Project 名称

在 `File -> Project Structure -> Project` 中修改 `Name`。

这一层更像界面显示名，只改它还远远不够。

### 第 2 步：再改 Module 名称

在 `File -> Project Structure -> Modules` 中修改模块名称。

很多运行配置和源码根路径都是跟模块绑定的，所以模块名不改，后面很容易出现“看起来改了，其实没全改”。

### 第 3 步：修改本地项目文件夹名称

这一步决定真实物理路径。  
一旦物理路径变了，IDEA 原来的 Content Root 通常就会失效。

### 第 4 步：回到 IDEA 修正 Content Root

如果路径已经红了，不要慌。  
这里的做法是对的：

1. 打开 `Project Structure -> Modules`
2. 找到右侧 `Sources`
3. 把旧路径的小叉删掉
4. 点击 `Add Content Root`
5. 重新选择改名后的模块目录

## 三、为什么这时运行项目常常会报错

因为到这一步时，IDEA 可能已经知道“你改了目录”，但某些运行配置、模块索引、缓存引用还没完全同步。

所以这里说的现象其实很常见：

- 项目结构看似已经改了
- 但一运行就报错

这不是 IDEA 神秘行为，而是旧结构引用还残留着。

## 四、为什么会自动冒出一个旧名字的空项目

这里记录的这一点特别典型：

> 回到文件夹中，IDEA 自动创建了一个原名称的项目，里面是空的。

这通常说明：

- IDEA 还在试图维护原来的项目根引用
- 物理路径和模块路径没有完全对齐

这时候不要在错误状态里继续修补。  
更省事的做法往往是直接把这个空壳删掉。

## 五、真正稳妥的收尾动作：关闭项目并重新导入

最后这一步非常关键：

1. `File -> Close Project`
2. 在最近项目列表里把旧项目叉掉
3. 点击 `Open or Import`
4. 重新选择改名后的项目目录

如果已经出现下面这些情况：

- 路径错乱
- 模块变红
- 运行配置异常
- 空壳项目自动生成

那重新导入通常比继续硬修更快。

## 六、把这件事理解成“重新对齐”而不是“改个名字”

真正发生的事情不是 rename，而是重新对齐这 4 层：

1. Project 显示名
2. Module 名称
3. 文件系统目录
4. IDEA 里的 Content Root

只有这四层重新一致，IDEA 才会恢复稳定。

## 七、最容易踩的误区

- 只改 Project 名，不改 Module
- 先改文件夹，再忘了 Content Root 还指向旧路径
- 路径红了还继续运行项目
- 已经出现空壳项目了还不重新导入

## 最后

IDEA 项目改名不是“改一个名字”，而是让项目名、模块名、物理路径和内容根路径重新对齐。  
只改一层，通常都会留下后患。
