# Linux 常用命令：开发排障最常用的一组动作

很多开发者平时并不把 Linux 当成主战场，直到某一天项目上线、服务报错、磁盘满了、内存飙了，才发现自己最缺的不是框架知识，而是基础命令能力。

这一篇虽然不长，但很实用，因为它记录的不是冷门命令，而是开发和运维现场最先会用到的那些动作。

## 一、先认清“我是谁”

### 当前用户

```bash
whoami
```

### 切换到 root

```bash
su root
```

很多权限问题的根因，不是系统坏了，而是当前用户身份不对。  
所以排障第一步，经常不是看日志，而是先确认“谁在操作机器”。

## 二、先看机器资源，不要一上来怀疑代码

### 查看磁盘

```bash
df -h
```

### 查看内存

```bash
free -h
```

### 查看 CPU 核数

```bash
lscpu | grep "CPU(s)"
```

如果服务起不来、日志刷不出来、机器变卡，这三条通常值得先执行。  
它们分别回答：

- 磁盘是不是满了
- 内存是不是顶住了
- 机器规格大致是什么

## 三、网络配置也是部署阶段的高频问题

### 查看网络信息

```bash
ip addr
```

这条命令最常见的用途是：

- 确认机器 IP
- 看网卡状态
- 排查服务监听和访问问题

## 四、目录和文件操作是部署时的基本功

### 创建多级目录

```bash
mkdir -p /mydata/redis/conf
```

`-p` 的价值在于：

- 父目录不存在也能一起创建
- 适合初始化挂载目录、配置目录、日志目录

## 五、会进入 vi 不等于会退出 vi

这里这两条很简单，但真的是服务器现场高频救命点。

### 不保存强制退出

```bash
:q!
```

### 保存并退出

```bash
:wq!
```

很多人第一次远程改配置，最先卡住的反而不是命令，而是不会退出编辑器。

## 六、把这些命令按场景记，比按分类背更有用

### 场景 1：服务起不来

优先看：

```bash
df -h
free -h
whoami
```

### 场景 2：目录不存在或挂载失败

优先看：

```bash
mkdir -p /目标目录
```

### 场景 3：远程访问异常

优先看：

```bash
ip addr
```

### 场景 4：改配置后想退出

```bash
:q!
:wq!
```

## 最后

Linux 常用命令最重要的价值，不是显得专业，而是让开发者在问题出现时，能迅速定位“机器层面到底发生了什么”。

先会这几条，很多部署和排障问题就不会完全抓瞎。
