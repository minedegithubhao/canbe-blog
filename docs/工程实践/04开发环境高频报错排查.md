# 开发环境高频报错排查：MySQL、PowerShell 和 Spring 接口错误怎么归因

很多环境报错的共同特点是：

- 看起来很吓人
- 搜出来的答案很多
- 但真正根因往往并不复杂

这一篇的价值，在于它不是泛泛列问题，而是记录了几个非常典型、非常高频、非常容易卡住开发节奏的报错。  
这次直接按“报错 -> 根因 -> 处理动作”的方式整理。

## 一、`HttpMediaTypeNotAcceptableException`

报错示例：

```plain
2025-01-23T21:06:46.574+08:00  WARN 22468 --- [nio-8080-exec-4] .w.s.m.s.DefaultHandlerExceptionResolver : Resolved [org.springframework.web.HttpMediaTypeNotAcceptableException: No acceptable representation]
```

这里的结论很直接，也很常见：

> 后端返回值对象缺少 getter、setter 方法。

也就是说，这类错误很多时候不是路由错了，也不是前端请求错了，而是对象没法被正常序列化。

排查顺序：

1. 先看返回对象是否完整
2. 再看 Jackson 是否能正常序列化
3. 最后才看请求头和响应头

## 二、`Public Key Retrieval is not allowed`

这是 MySQL 连接里的高频坑。

报错：

```plain
Public Key Retrieval is not allowed
```

这里给出的原因是：

- MySQL 从 5.7 到 8.0 后，认证方式有变化
- 新用户默认可能使用 `caching_sha2_password`
- 客户端不支持新的加密方式

解决办法：

```sql
ALTER USER 'root'@'localhost' IDENTIFIED WITH mysql_native_password BY 'root';
```

执行成功后：

```plain
mysql> ALTER USER 'root'@'localhost' IDENTIFIED WITH mysql_native_password BY 'root';
Query OK, 0 rows affected (0.00 sec)
```

这类错误的关键判断是：

> 不是网络问题，而是认证插件和客户端能力不匹配。

## 三、`Host 'xxx' is not allowed to connect to this MySQL server`

报错示例：

```plain
Host 'XXX-XXX' is not allowed to connect to this MySQL server
```

这里给出的根因是：

- MySQL 默认限制可访问的主机
- 某个用户可能只允许 `localhost` 登录

先查用户和 host：

```sql
select user,host from mysql.user;
```

如果看到：

```plain
| root | localhost |
```

就说明 root 只允许本机访问。

修改方式：

```sql
update mysql.user set host = '%' where user = 'root';
FLUSH PRIVILEGES;
```

但这里一定要保留这里的提醒：

> 生产环境不要为了省事直接给所有用户开放 `%` 访问权限。

## 四、`npm.ps1 无法加载，因为在此系统上禁止运行脚本`

报错示例：

```powershell
npm : 无法加载文件 C:\Program Files\nodejs\npm.ps1，因为在此系统上禁止运行脚本。
```

这类错误的本质不是 npm 有问题，而是 PowerShell 执行策略拦住了脚本。

解决方法：

```powershell
Set-ExecutionPolicy RemoteSigned
```

执行后输入 `Y` 确认即可。

这一类问题最容易误判成“Node 安装坏了”，但其实是：

- 工具没坏
- 系统策略不允许

## 五、`ERROR 1045 (28000): Access denied for user`

这里记录的是：

```plain
ERROR 1045 (28000): Access denied for user ‘ODBC’@‘localhost’ (using password: NO)
```

这类错误很多时候就是最朴素的原因：

- 用户名不对
- 密码不对
- 认证方式不对

如果已经需要重置密码，这里的顺序可以直接照做：

### 1. 跳过密码验证

```powershell
mysqld --skip-grant-tables
```

### 2. 登录 MySQL

```powershell
mysql -uroot -p
```

### 3. 修改密码

```powershell
ALTER USER 'root'@'localhost' IDENTIFIED BY '123456';
```

或者：

```powershell
ALTER USER '用户名'@'localhost' IDENTIFIED WITH mysql_native_password BY '密码';
FLUSH PRIVILEGES;
```

## 六、把这些错误按层次归类，排查会快很多

其实这几类高频报错，本质上属于不同层：

### 1. Spring 返回格式层

- `HttpMediaTypeNotAcceptableException`

重点看：

- 返回对象
- getter / setter
- 序列化

### 2. MySQL 认证层

- `Public Key Retrieval is not allowed`
- `Access denied for user`

重点看：

- 认证插件
- 密码
- 用户账户

### 3. MySQL 主机权限层

- `Host 'xxx' is not allowed to connect`

重点看：

- `mysql.user`
- `host`
- 授权范围

### 4. PowerShell 系统策略层

- `npm.ps1 无法加载`

重点看：

- Execution Policy

## 最后

高频环境报错并不可怕，可怕的是不先判断它属于哪一层。  
只要先分清是：

- 返回格式
- 认证机制
- 主机权限
- 系统策略

排查思路通常就已经对了一半。
